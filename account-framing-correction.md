# Correction: the existing non-`.ru` Cursor account is not required

## Original framing

Early escalation described the goal as linking the paid X/xAI identity to an existing Cursor account whose email address did not match the X identity.

## Corrected requirement

On **2026-09-03 UTC**, the customer clarified that the existing non-`.ru` Cursor account is **not** required. A new personal Cursor account using the same valid `.ru` address as the paid X/xAI identity is acceptable.

## Why the correction matters

The unresolved question is therefore not whether Cursor must support cross-email linking. It is whether the advertised SuperGrok Heavy benefit has any supported path when the paid X/xAI identity uses a valid `.ru` email address, and whether the permanent-link warning can be navigated without consuming the entitlement on an unintended account.

This correction supersedes any earlier statement that access must work specifically on the existing non-`.ru` Cursor account. It does **not** prove that the `.ru` suffix is the backend trigger; Cursor has not confirmed the evaluated policy.

## Resolution test

Resolution requires a successful new-account or linking path using the paid identity, followed by live confirmation that Grok Bot access is available. A support assurance without a working product result is not sufficient.
